ClassTell 使用说明
版本：v1.0.0a_1（.NET Framework 4.8 / WinForms）
生成日期：2026-09-25（第 3 版：取消软件自有的弹窗与浮层，全部改用系统通知/系统对话框；详情页改为页内视图）
====================================================================

一、这是什么
--------------------------------------------------------------------
ClassTell 把“邮件”当作远程指令使用：
  · 用 OAuth2（Modern Auth）登录 Outlook / Microsoft 365 邮箱；
  · 收信方式二选一（默认 Microsoft Graph，可在“高级设置 → 收信方式”切换）：
      · Microsoft Graph：轮询收件箱未读邮件（GET /me/messages，权限 Mail.Read）——推荐，
        个人 outlook.com 账号即使 IMAP 被禁用也能收信；
      · IMAP：outlook.office365.com:993 / SSL-TLS + XOAUTH2（需要邮箱侧已开启 IMAP）；
  · 邮件标题写命令字，正文第一行当标题、后面当正文；
  · 收到“呼叫”类指令会弹出系统通知（通知区域气泡），并把内容显示在消息界面。

二、运行环境
--------------------------------------------------------------------
· Windows 7 SP1 / 8.1 / 10 / 11（建议 Windows 10 及以上，通知区域更完整）；
· .NET Framework 4.8 运行时（Win10 1809 以上系统自带）；
· 需要能访问 login.microsoftonline.com:443；Graph 模式还需 graph.microsoft.com:443，
  IMAP 模式还需 outlook.office365.com:993（公司网络若拦截这些地址会导致收信失败）。

三、安装与启动
--------------------------------------------------------------------
1) 把发布目录（bin\Release\net48 或 bin\Debug\net48）整体复制到任意位置；
2) 双击 ClassTell.exe。首次启动会自动跳到“关于 → 邮箱登录”并打开浏览器要求登录；
3) 程序是单实例的，重复启动会提示“已经在运行中”。

启动参数（可选，用于诊断）：
  ClassTell.exe --no-login     不自动弹出登录（离线查看界面）
  ClassTell.exe --demo         注入 5 条示例消息并模拟一次“C / call”通知，便于预览动效

四、邮箱登录（OAuth2 / Modern Auth）
--------------------------------------------------------------------
• 服务器：outlook.office365.com    端口：993    加密：SSL/TLS    认证：OAuth2（Modern Auth）
• 方式一“使用浏览器登录”：调用系统默认浏览器完成微软账号登录，支持个人 Outlook.com
  账号，也支持工作/学校账号（MFA、条件访问等由微软页面自行处理）。
• 方式二“使用设备代码登录”：无浏览器/远程桌面场景使用。程序会给出形如 XXXX-XXXX 的
  设备代码，请在任意设备打开 https://microsoft.com/devicelogin 输入该代码。
• 登录成功后令牌缓存在本机（%APPDATA%\ClassTell\msal_token_cache.bin），下次启动免登录
  自动静默刷新；点“退出登录”会清空缓存。
• 高级设置里的四项可自行修改：
    客户端 ID：公共客户端 ID（默认使用第三方邮件客户端通用的公共客户端 ID，
               可直接登录；建议替换为你在 Entra ID 自己注册的应用）
    租户：common（默认，个人+组织）、consumers（仅个人）、organizations（仅组织）
          或你的租户域名/租户 ID
    权限范围：随“收信方式”显示对应权限：
              Graph 模式默认 https://graph.microsoft.com/Mail.Read（收正文必需，
                        若只列元数据可用 Mail.ReadBasic，但程序无法读取正文）；
              IMAP 模式默认 https://outlook.office.com/IMAP.AccessAsUser.All
                        （需要发信可再加空格分隔的 https://outlook.office.com/SMTP.Send）
    收信方式：Microsoft Graph（默认，推荐）/ IMAP —— 点一下即可切换、立即生效；
              切换后需要重新登录一次以同意新权限（Graph 需要 Mail.Read）。
• 自己注册应用的步骤（推荐）：Entra 管理中心 → 应用注册 → 新注册
  （账户类型选“任何组织目录中的账户和个人 Microsoft 账户”）→ 平台选“移动和桌面应用程序”，
  重定向 URI 填 http://localhost → 在“身份验证”里打开“允许公共客户端流”→
  在“API 权限”里添加 Office 365 Exchange Online 的 IMAP.AccessAsUser.All（可再加 SMTP.Send）；
  用 Graph 收信则添加 Microsoft Graph 的 Mail.Read（委派权限）即可。
  把“应用程序(客户端) ID”填到高级设置里即可。

五、邮件格式约定（必须严格按此格式）
--------------------------------------------------------------------
（提示：本软件不使用任何自有弹窗；所有提醒都通过系统通知区域与系统对话框呈现，见第六节。）
标题：AAAA          ← 命令字
正文第一行：BBBB    ← 消息标题
第一行之后：CCCC    ← 消息正文（保留换行，完整显示）

命令字取值：
  C  或  call  → 呼叫：弹出系统通知（通知区域气泡），同时显示在消息界面
  T  或  tell  → 提示：只在消息界面显示，不弹通知
  其它内容 → 忽略该邮件（会写进日志，便于排查）

通知（C / call）内容格式：
  标题：BBBB
  内容：CCCC（会保留换行；过长时自动截断并加“…”）
  来源于：发件人邮箱地址

说明：命令字大小写不敏感，前后空格会被忽略，形如“[C]”“CALL”也能识别；
      正文第一行若写成“标题：xxx”，前缀会被自动去掉。

六、界面与提示说明
 --------------------------------------------------------------------
 【弹窗策略】本软件没有任何自有的弹窗 / 浮层窗口：
   · “呼叫”提醒（标题为 C / call 的邮件）-> 系统通知气泡 + 任务栏闪烁 + 窗口标题
     显示“【呼叫】<标题>”；窗口若在托盘会自动召回（保证一定看得见）；
   · 运行状态（正在检查新邮件、已登录、已连接、收取出错等）-> **只在软件内提示**：
     显示在窗口标题（形如 “ClassTell 邮箱指令通知 · 正在检查新邮件…”，约 6 秒后自动还原），
     **不再走系统通知通道**；
   · 需要用户确认的错误（登录失败、登录状态失效等）-> 系统对话框（Windows 消息框）；
   · 程序内只有一个主窗口；自测会校验“程序集内除主窗口外不存在任何窗体类型”，
     并校验“发送通知不会创建任何窗口”。

【托盘与后台运行】
   · 关闭窗口默认**不退出程序**，而是隐藏到通知区域（托盘）继续收信；
   · 托盘图标右键菜单：显示主界面 / 立即收取 / 退出 ClassTell（真正退出）；
   · 左键点击托盘图标 = 显示主界面（有未读呼叫则直接打开该消息详情）；
   · 想改成“关闭即退出”：关于页 → 界面与常规设置 → 关闭窗口时 → 关掉开关；
   · 开机自启动开启后，程序以 `--tray` 启动：开机后直接在托盘静默运行并开始收信。

左侧导航栏：
  · 消息（启动后自动进入）
  · 关于

【消息页】
  · 邮件以“田”字形（2×2，每页 4 条）展示，最新的一条在最前；
  · 底部“第 x / y 页”配合 `<` `>` 按钮前后翻页，翻页带 Material 位移动效；
  · 卡片显示命令角标（呼叫 C / 提示 T）、标题（字号大于正文）、正文预览（保留换行、
    超出打省略号）、来源与时间；
  · 点击卡片会**在本页内直接打开完整内容**（标题 + 完整正文，可滚轮浏览），
    右上角“‹ 返回列表”或 Esc 返回；这是页内视图，**不是弹窗**；
  · 右上角显示连接状态（未连接 / 正在连接 / 实时接收中 / 出错）与“立即收取”按钮；
  · 消息只保存在内存里，重启软件后清空（按需求设计）。

【关于页】（可滚动，三段）
  1. 邮箱登录：账号状态、浏览器登录 / 设备代码登录、退出登录、高级设置
  2. 界面与常规设置：
     · 字体大小滑块：8~16 pt（默认 10pt；界面按字体度量自适应排版，最大字号也不会被裁切）
     · 深色 / 浅色模式开关：实时切换，窗口标题栏也会跟随系统深/浅外观
     · 配色方案：4 套强调色色卡，点一下立即生效并记住
        - 水蓝 #7AB5D6（默认，浅色底文字 #2E7CA8）
        - 青碧 #48C0A3（浅色底文字 #12816A）
        - 丁香 #B57EDC（浅色底文字 #7B44B0）
        - 杏黄 #FFA631（浅色底文字 #A66300）
       （色值取自常见中国传统色/常用网页配色；浅色模式下自动使用加深版本，保证文字对比度）
     · 关闭窗口时：保持在后台（托盘）运行 / 直接退出（默认保持后台）
     · 开机自动启动：写入当前用户启动项（HKCU\Software\Microsoft\Windows\CurrentVersion\Run
       下的 ClassTell 值，命令行为 "<程序路径>" --tray），开机后在托盘静默启动；无需管理员权限
  3. 开发者信息：只显示版本号 v1.0.0a_1，以及程序目录下 info.txt 的内容
     （用微软雅黑渲染；除版本外不再内置任何开发信息；
       info.txt 不存在时，内容显示为 Err:NotExist）

窗口说明：主窗口使用系统标准窗口组件（原生标题栏、最小化/最大化/关闭、系统拖动与缩放），
         并在 Windows 11 下启用系统圆角；程序图标与托盘图标会随配色一起变色。
         按钮、卡片、导航项、分页按钮、输入框、滚动条全部为圆角，
         其中登录用的输入框是圆角容器（内部仍是系统输入框，支持中文输入法与复制粘贴）。
         按钮宽度按文字内容自动计算并自动换行，任何字号/缩放下都不会出现文字被截断。
         分页按钮使用 “<”“>” 文字符号；若系统缺少图标字体，其余图标会自动退化为文字符号，
         因此不会出现乱码方块。

快捷键：Ctrl+1 消息页 · Ctrl+2 关于页 · F5 立即收取 · Esc 返回消息列表（关闭页内详情）

七、动效、配色与屏幕适配
--------------------------------------------------------------------
· 配色：深色模式（#121316 / #1B1D21 底 + 高对比文字）与浅色模式（白色简约底 #FFFFFF /
  #F3F6F9 卡片）两套完整配色；强调色可在 4 套方案中切换（见“关于 → 界面设置”）。
  浅色模式下强调色文字自动使用加深版本、投影自动减弱；导航栏、滚动区、输入框、按钮、
  滑块、色卡等所有自带底色的控件都会随模式切换，不会残留另一种模式的底色。
· 动效：Material 标准缓动（cubic-bezier(0.4,0,0.2,1) 等）、按钮水波纹、导航选中位移、
  页面切换的交叉淡入 + 共享轴位移、页内详情上滑、卡片悬停上浮、
  配色/模式切换即时生效（无需重启）。
· 屏幕适配（响应式，非针对某一固定分辨率写死）：
  - 字号以磅定义、按像素渲染：像素 = 磅 × 系统 DPI ÷ 72。100% 缩放下 10pt≈13px；
    200% 缩放下物理像素翻倍而“逻辑尺寸”不变，因此不会出现高缩放字体被放大两遍而拥挤、
    低分辨率下字体过小的问题。
  - 启动时按“系统 DPI + 可用显示区域（物理像素 ÷ 缩放 = 逻辑区域）”计算：
      · 紧凑系数：逻辑区域 < 1366×800 → 0.84；< 1680×1000 → 0.92；其余 1.00
        （只收紧间距/圆角/导航宽度，不缩小字体，避免内容被挤压）
      · 首次运行的推荐字号：按逻辑高度在 9 ~ 10.5pt 之间自动选择
  - 默认字号 10pt（范围 8~16pt，可在“关于 → 界面设置”调整并记住）。
  - 所有行高、页头页脚、卡片内边距、按钮高度、翻页控件都按字体度量推导，字号变化后
    不会出现重叠、截断或错位；窗口尺寸也按工作区自动收缩，高缩放/小屏下不会超出屏幕。
· 字体：统一微软雅黑（Microsoft YaHei）。

八、数据与日志位置
--------------------------------------------------------------------
%APPDATA%\ClassTell\settings.ini            设置（可手工编辑，key=value）
                                            其中 DarkMode=true/false 为深/浅色模式，
                                            AccentKey=water/teal/lilac/apricot 为配色方案，
                                            FontSize 为字号（9~20）
%APPDATA%\ClassTell\msal_token_cache.bin    登录令牌缓存（退出登录会删除）
%APPDATA%\ClassTell\log.txt                 运行日志（排查登录/收信问题用）

与程序同目录的 info.txt 会显示在“开发者信息”里；删除后可看到（Err：Not_Exist）。

九、常见问题
--------------------------------------------------------------------
1) 提示“登录状态已过期/需要重新登录”：在“关于 → 邮箱登录”里重新登录即可。
2) 登录报权限/同意错误：确认邮箱是 Microsoft 365 或 Outlook.com；若组织要求管理员同意，
   请改用自己注册的应用（见第四节），或让管理员为默认客户端 ID 授权。
3) 一直“正在连接”：检查网络/代理是否允许 993 端口与 TLS；公司网络若做了 IMAP 拦截，
   需联系管理员。日志里会记录具体错误。
4) 登录成功却提示“认证被拒绝：邮箱需开启 IMAP”（状态栏 + 系统对话框会给出处理步骤）：
   这说明登录与令牌都正常，只是该邮箱在服务器侧没有开放 IMAP（个人 outlook.com 账号默认关闭）。
   处理办法（任选其一）：
     · 【推荐】改用 Graph 收信：「关于 → 邮箱登录 → 高级设置 → 收信方式 = Microsoft Graph」
       → 点“保存并重新登录”，在浏览器里同意 Mail.Read；Graph 收信不依赖 IMAP 开关。
     · 若要用 IMAP：Outlook.com 个人账号用浏览器打开 https://outlook.live.com → 齿轮“设置”
       → “邮件 → 同步电子邮件”，打开“允许设备和应用使用 POP 和 IMAP”，保存；等 5~10 分钟后
       回到本软件点“立即收取”（或按 F5），无需重启。
     · 工作 / 学校账号：让管理员在 Exchange 管理中心为该邮箱启用 IMAP
       （快速确认：管理员执行 Get-CASMailbox -Identity <邮箱> | fl ImapEnabled）。
     · 仍然失败：运行 `--mail-check` 诊断（见第十节）把结论反馈给开发者。
     · 程序只会提示一次系统对话框，之后仍会按退避重连（状态栏持续显示该状态）。
5) 提示“需要重新登录（Graph）”：说明缓存里的令牌还是旧权限；到“关于 → 邮箱登录”点“登录”，
   在浏览器完成一次授权（同意 Mail.Read）即可；之后长期静默刷新，无需反复登录。
6) 收不到新邮件：确认网络能访问 graph.microsoft.com（Graph 模式）或 993 端口（IMAP 模式）；
   IMAP 模式优先用 IDLE 实时推送（服务器不支持时退化为轮询，间隔默认 20 秒，可改 PollSeconds），
   Graph 模式按 PollSeconds 轮询未读邮件（点“立即收取”可立刻检查一次）。
7) 同一个未读邮件每次启动都会显示：默认不改变邮箱状态（MarkAsSeen=false），
   启动时会回溯最近 10 封未读（RecentScanCount 可调 0~200，0 表示只收启动后的新邮件）。
8) 呼叫（C / call）没有弹出通知：本软件对呼叫做了三路提醒——系统通知气泡 + 任务栏闪烁
   + 窗口标题显示“【呼叫】标题”（窗口在托盘会自动召回）。若三路都看不到，请检查：
   · Windows“设置 → 系统 → 通知”里是否允许该程序、是否开启了“专注助手/勿扰”；
   · 任务栏右下角通知区域是否把本程序图标收进了溢出面板（气泡仍属系统通知，受上面开关控制）；
   · 确认邮件的**标题**确实是 C / call（标题为 T / tell 的邮件只进列表，不提醒），
     并且“关于 → 邮箱登录”页面里的账号处于已登录状态。
9) 关闭窗口后程序还在运行：这是默认行为（驻留托盘继续收信）。要彻底退出，请右键托盘图标 →
   “退出 ClassTell”；想改成关闭即退出，到「关于 → 界面与常规设置 → 关闭窗口时」关掉开关。
10) 开机自启动怎么关：同上设置卡里的“开机自动启动”开关关掉即可（会同时删除注册表启动项）；
   也可以在系统“任务管理器 → 启动”里禁用。
11) 通知里显示“【呼叫】”但窗口自己跳出来了：这是设计如此——窗口在托盘时收到呼叫会召回主窗口，
   确保你能看到；若不想让呼叫提醒窗口，把 `%APPDATA%\ClassTell\settings.ini` 里的
   `NotifyOnCall` 改成 false（改为 false 后标题为 C/call 的邮件只进列表、不再提醒）。
   或“聚焦助手/勿扰模式”是否开启；此类系统开关由 Windows 自身控制，程序不做额外弹窗。

十、开发者：自行编译与自测
--------------------------------------------------------------------
· 环境：.NET SDK 8（或 VS 2022）即可编译 net48 目标（已引用 Microsoft.NETFramework.ReferenceAssemblies，
  无需安装 VS 工作负载）；依赖 MailKit 4.8.0 与 Microsoft.Identity.Client（MSAL）4.67.2。
· 编译：  dotnet build ClassTell.sln -c Release
· 运行：  bin\Release\net48\ClassTell.exe
· 自测：  tests\ClassTell.SelfTest\bin\Debug\net48\ClassTell.SelfTest.exe
          （493 项检查：指令解析、正文拆分、截断、HTML 转换、设置读写（含废弃配置项清理）、缓动曲线、
            OAuth2 参数、收信失败提示（含 Outlook 未开启 IMAP 的可执行提示）、
             邮箱诊断辅助（--mail-check 开关解析、XOAUTH2 用户名候选去重）、
             Graph 收信（未读列表 URL、JSON 解析与转义、MIME→指令解析链路、收信方式与权限切换）、
             运行方式（关闭驻留托盘 / 开机自启动开关与自启动命令行、收信方式切换按钮、托盘开关）、
             info.txt 缺失处理、
            深/浅色模式与 4 套配色切换、
            8~16pt 各字号下的田字格与关于页排版（卡片不重叠、文字不裁切）、

· 邮箱诊断：tests\ClassTell.SelfTest\bin\Release\net48\ClassTell.SelfTest.exe --mail-check
          （只读，不发信、不改邮箱：取令牌 → 令牌格式/实际权限/缓存种类 → Graph 邮件探针 →
            IMAP 多用户名 A/B → POP3/SMTP 交叉探针 → 结论矩阵。开关：
              --interactive        允许为 POP/SMTP/Graph 走一次设备代码同意（不加则跳过这几个探针）
              --imap-user <地址>   指定 XOAUTH2 用户名做 A/B 测试（可重复）
              --imap-basic         用应用密码做原生 LOGIN 探针（成功即说明 IMAP 确实已开启）
              --skip pop,smtp,graph 跳过指定探针
              --out diag.txt       输出同时写入文件，便于反馈
            加参数可临时换租户，例如 --mail-check consumers；诊断结束自动还原设置）
